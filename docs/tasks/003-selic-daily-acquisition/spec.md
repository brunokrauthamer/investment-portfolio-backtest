# Selic daily acquisition — specification s001

Status: proposed 2026-11-03; awaiting explicit human approval together with plan p001. Implementation and acquisition are not yet approved by this proposal.

## Goal and proposed conventions

On explicit invocation, scrape Banco Central do Brasil's SGS series 11 chart and every page of its values table, beginning with the first available observation in 2011 and ending with the latest source-published observation at run time. Series 11 is the daily effective Selic rate in percent per day, not the annual policy target or an investment return. Save one generated UTF-8 CSV at `data/selic/source/selic_sgs_11.csv` with headers `date,rate_percent_per_day`, one observation per row, ascending date, ISO `YYYY-MM-DD` dates and a period decimal separator. Preserve every digit of the displayed percentage without rounding, binary floating point, division by 100, annualization, interpolation or derived returns. For example, displayed `03/01/2011 | 0,040239` becomes `2011-01-03,0.040239`. This is a transcription of displayed observations, not a source-original file. No missing dates are invented.

Use the chart page's own latest-value date as `dataFim`; start the filter at `01/01/2011` so the first published 2011 observation is included. Select the default Linear function, click Refresh chart, then View values from chart, and follow every page of the returned table. The observed first 2011 date is 03/01/2011; neither that date nor the latest date may be hard-coded as a run-time result. If BCB changes the interface, makes coverage ambiguous, or denies access, fail clearly rather than circumvent protections or claim completeness. BCB data may be revised; every explicit run reacquires the complete range.

## Acceptance criteria

- **AC-001 Explicit entry:** Register `selic` in the shared getter registry for `acquire("selic", data_dir)`, `acquire_all`, and `python -m backend.src.internet_data_getter --getter selic`; imports, CLI help and application startup make no network requests. Failures produce an incomplete report and a nonzero CLI result. Do not add an API, scheduler, frontend, or background network work.
- **AC-002 Correct source and range:** On a run visit the user-specified SGS 11 chart, verify series identity, unit and last-value date, set the inclusive start and source-reported latest end, refresh the chart and open its values. Verify the resulting table's selected series, period, Linear function and `% p.d.` unit. Capture the latest date from that invocation, not the system clock or a fixed date. Dates outside the requested range are rejected.
- **AC-003 All pages:** Traverse every values page to the source-indicated end. Parse only observation rows and preserve their displayed rates. Require valid dates/decimal text, strictly increasing unique dates, consistent page metadata and total count equal to the source count. Require nonempty results, a first observation in 2011, and a final observation matching the source-reported latest date. Repeated/missing pages, truncated responses, wrong series, conflicting dates, changed metadata, timeouts and access errors produce an explicit incomplete result; no partial result is published as complete.
- **AC-004 CSV and provenance:** For a complete run save the specified deterministic CSV, exact textual decimal precision and chronology; record source page URL, SGS code, unit, requested and actual coverage, reported and acquired counts, retrieval time, CSV hash and data format in `data/selic/manifest.json`. Record access and usage information including BCB's listed ODbL license; do not imply legal conclusions. Report saved, updated or unchanged and range/count.
- **AC-005 Safe reruns:** Unchanged data leaves the CSV untouched and creates no backup. Before replacing existing changed CSV or manifest data, preserve recoverable verified backup(s) outside active inputs under `data/backups/selic/`. Stage files as temporary siblings and use atomic replacement; a write-ahead recovery record must remain until CSV and matching provenance are committed. Recovery must recognize old/new hashes, retain backup references, and stop safely on ambiguous state. Failed or interrupted acquisition, validation, backup, replacement or recovery must not leave an active CSV partially written or silently lose its previous version. Document offline restore and stale-lock procedure. An exclusive acquisition/restore lock rejects overlapping work without altering active data; never silently break a live lock.
- **AC-006 Tests and documentation:** Test source selection, browser interactions, every-page traversal/count/identity and value precision, error conditions (including repeat, missing and malformed pages, latest mismatch, no data and source denial), registration and no-network import, plus unchanged/changed writes, backups, recovery, lock and failures. Tests use controlled non-market fixture observations and no network. Document dependencies, browser installation, command, schema/units, source provenance/terms, failure behavior and restore.
- **AC-007 Live evidence:** Independently exercise the documented command against the live BCB page and compare counts, first and last dates and representative first/middle/last values against the actual paged source; record time, observed coverage and result. Failure or unavailable access is blocked, not a pass. After checks, run the acquisition to the project data directory when live access succeeds and validate the resulting CSV and manifest.

## Exclusions and observations

No backtesting, financial interpretation beyond source units, asset pricing, returns, missing-day filling, annualization, redistribution, scheduling or other assets. During read-only discovery on 2026-11-03 (America/Sao_Paulo), the chart showed latest date 30/10/2026. The 01/01/2011–30/10/2026 Linear table reported 3,976 rows across 40 pages, starting 03/01/2011. These are observations, not fixed test fixtures or a guarantee of future source behavior. BCB's [dataset page](https://dadosabertos.bcb.gov.br/dataset/11-taxa-de-juros---selic) identifies series 11 as daily `% a.d.` and lists an ODbL license. It notes limits on its JSON/CSV resources; this proposal uses the user-requested chart/table interface, not those endpoints.
