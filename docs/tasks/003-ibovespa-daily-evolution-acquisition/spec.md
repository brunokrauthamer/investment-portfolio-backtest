# IBOVESPA daily-evolution acquisition — specification s001

Status: proposed 2026-11-03; awaiting explicit human approval with plan p001. This proposal is not authorization to implement.

## Goal and scope

On explicit invocation, acquire B3's original annual IBOVESPA daily-evolution CSV downloads from 2011 through the current calendar year, including the current partial year. Use the [B3 IBOV page](https://sistemaswebb3-listados.b3.com.br/indexStatisticsPage/daily-evolution/IBOV?language=pt-br) and the same architecture, checks and data-safety behavior as the existing IFIX getter. No network calls on import or application startup. This is personal-use source acquisition, with no assumption of redistribution rights.

## Acceptance criteria

- **AC-001 — selection and entry points:** An explicit run requests each year 2011 through the current local calendar year, without a hard-coded final year. The registered name `ibovespa` works through both shared Python `acquire`/`acquire_all` and CLI `--getter ibovespa`/default all-getters paths. Existing IFIX entry points and behavior remain intact. Unknown getter names fail before contacting the network.
- **AC-002 — original data and provenance:** Each valid annual download is stored with its exact decoded original CSV bytes in a distinct stable name under `data/ibovespa/source/`, with year and source filename in its name. `data/ibovespa/manifest.json` records period, source filename and page URL, retrieval time, SHA-256, and version history. Do not normalize, merge, transform, fill gaps or generate market observations.
- **AC-003 — validation and completeness:** Inspect B3's actual IBOVESPA response format and endpoint before finalizing validation. Apply IFIX-equivalent checks adapted to the observed index label and format: response status, valid transport encoding, expected year and index header, month columns, 31 day rows, complete summary structure and at least one daily observation; allow blank future months in current-year files. Reject malformed, wrong-index, wrong-year, truncated, empty, denied or unexpected responses. Failed years and storage failures are identified, remaining years continue, and any failure or empty year range produces incomplete report and nonzero CLI exit.
- **AC-004 — safe reruns and restoration:** Identical bytes leave active file and its modification time unchanged with no backup. Before replacing changed data, create and verify a recoverable backup under `data/backups/ibovespa/<year>/`, then use atomic replacement and write-ahead manifest recovery equivalent to IFIX. A failed download, backup, manifest update or replacement must not partially write or lose old active data or silently lose backup references. A documented offline restore validates the backup and protects displaced active bytes. Existing IFIX data, backups and manifest remain untouched by an IBOVESPA-only run.
- **AC-005 — isolation and concurrency:** Separate source, orchestration and storage responsibilities within `internet_data_getter`, register the getter and commands in the shared entry points, and keep asset-specific behavior in its directory. Reject overlapping IBOVESPA runs before downloading or mutating data; document safe stale-lock recovery. Enforce bounded timeout, pacing and normal TLS verification; do not bypass access restrictions.
- **AC-006 — automated verification and docs:** Tests cover year range, registry and CLI selection, exact bytes/provenance, every validation check, invalid transport and HTTP responses, partial failures, unchanged/changed files, verified backups, restore, interrupted writes/recovery, invalid manifests and overlap. Controlled test payloads must not invent market history. Document installation, command, layout, validation, provenance, actual observed source limitations, backup and restoration. Run the existing getter test suite and relevant integrated checks.
- **AC-007 — source-backed evidence:** When source access is available, independently verify a complete documented invocation and compare earliest and current-year local bytes to B3 downloads. Record actual source format, range, constraints and results. If source access prevents this, record the concrete blocker; do not report the criterion as passed.

## Exclusions and source gate

No API/frontend, scheduler, financial calculations, normalized series, new assets or unrelated data changes. The browser-accessible page returned no readable content to the initial web reader on 2026-11-03; the IBOV endpoint, index label, format and access terms are not yet verified. Source inspection is a required implementation gate. If actual B3 behavior conflicts with these criteria or a financial/data convention needs a new decision, stop and ask for revised approval; do not invent results or bypass restrictions.
