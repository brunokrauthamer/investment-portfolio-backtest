# Portfolio backtest — specification s001

Proposed 2026-11-04 (America/Sao_Paulo); approval of s001 and plan p001 is pending. This is a new task under the simple-feature-workflow; it does not change the status of task 006-portfolio-configuration.

## Scope and contract

Calculate the requested portfolio from the existing `data/normalized/daily_returns_reais.csv` using the existing `POST /api/portfolio` request shape and validation. CSV columns are `date,ibovespa,ifix,selic,sp500`; asset cells are decimal daily returns and an existing zero is used as zero. There is no network access, data generation, initial currency amount, or initial value in the result. Available CSV dates within the inclusive range appear once in chronological order, including either boundary when present.

For each row, start from weights in force at the beginning of that row. Its portfolio decimal return is the sum of weight times asset decimal return. Accumulate compounded return as `growth *= 1 + daily_return`; report `(growth - 1) * 100`. After the row, drift each weight to `weight * (1 + asset_return) / (1 + daily_return)`. Initialize target weights from requested percentages divided by 100; do not round intermediate values. Selic is treated identically to other daily return columns.

Rebalancing `none` never resets weights. For each other existing strategy, schedule anniversaries at every 3, 6, 12, 24, or 36 calendar months from the first available row in the requested range. Determine every anniversary from that original anchor; when a target month lacks the anchor's day, clamp to that month's last day. On the first available row on or after an anniversary, use the existing weights for that row's return, then reset to target weights for the next row. If a gap spans multiple anniversaries, consume all anniversaries through that row and reset once. Repeat throughout the range.

For a valid request, HTTP 200 returns `{"series":[{"name":"Cumulative portfolio return","data":[...]}]}`. Each point has exactly these fields: `x` (integer UTC-midnight Unix milliseconds), `y` (cumulative return in percentage points), `date` (ISO `YYYY-MM-DD`), `daily_return_pct` (daily return in percentage points), and `cumulative_return_pct` (the same number as `y`). The first row's return contributes to daily and cumulative values. No extra initial point is added. A valid range with no rows returns the same series with empty `data`; the frontend clearly reports that no data is available for that range.

The frontend retains its existing default dates, `2011-01-04` and `2026-10-30`, allocations and rebalancing choices. On a successful nonempty result, pass the API's `series` directly to ApexCharts and display the cumulative portfolio return. Before a result, use an explicit empty state. When settings change, clear or clearly invalidate the previous result so it cannot be mistaken for the current settings. Show loading, empty and actionable failure states; no false acknowledgement. Keep the existing date/percentage and index selection validation and retry behavior.

## Acceptance criteria

- **AC-001 — Data and range:** pandas reads and filters the existing file in the backend model layer. Selected range endpoints are inclusive; all matching unique dates appear chronologically once; non-row dates are not invented. An empty range returns an empty series. Data remains read-only.
- **AC-002 — Daily return and drift:** Initial target allocations apply to the first row. Each daily return uses start-of-day weights; drift follows relative asset performance after each row. Zero observations are used as zero; Selic compounds like the other assets. Compounding includes the first row and uses no intermediate rounding, currency amount, or initial value.
- **AC-003 — Schedule:** Each of the six existing rebalancing choices behaves as specified above, including repeated anniversaries, an anniversary missing from the CSV, month-end/leap-day clamping and gaps spanning multiple anniversaries. Reset applies only after the triggering row.
- **AC-004 — Chart response:** The exact series structure and point fields above contain numeric percentage points, `y` equal to cumulative return, integer UTC-midnight timestamps and ISO dates, with first-row return included. `response.series` is passed to ApexCharts directly without data mapping, date parsing or reshaping.
- **AC-005 — User experience:** The specified default dates are visible. Submitting valid settings displays the returned cumulative chart, and an empty range has a clear empty message. Changes cannot leave an old chart presented as a result for new settings. Pending, request, CSV and malformed-response failures are visible and do not show a success acknowledgement or fictional historical result. The form remains usable and accessible, including date/allocation errors and retry.
- **AC-006 — Errors and safety:** Existing input validation continues to reject invalid dates, percentages, duplicate/unknown indexes and fields, strategies, malformed or duplicate-member JSON and nonfinite input without successful acknowledgement. Valid requests with missing/unreadable/malformed data return a clear non-2xx error rather than a false result; invalid CSV schema, dates, duplicate/nonascending dates, nonnumeric/nonfinite return values and returns below -100% are rejected. If the entire portfolio becomes worthless so drift cannot be computed, return a clear non-2xx calculation error. No file or network access happens during module import/startup; no source data is modified.
- **AC-007 — Boundaries and evidence:** CSV loading/filtering is in `api/model`, calculations/scheduling in `api/service`, and the controller handles HTTP delegation with API-independent service errors translated at the app boundary. Preserve existing health/index behavior and strict JSON contract. Record meaningful test-first red and green evidence, run relevant backend/frontend checks, independent review and independent QA, including browser exercise when available. Document the changed API and frontend behavior and runtime dataset requirement.

## Proposed error and display details

Invalid input returns 422 with a clear safe detail. An unavailable, malformed or unusable dataset, or an undefined calculation, returns 503 with a clear generic detail and without exposing local filesystem paths. The data adapter checks required columns and valid, unique, strictly ascending dates; it validates selected row values as finite numbers at least -1. A -1 return is permitted for an individual asset, provided the portfolio's aggregate growth factor for the row remains positive. Empty filtered data is not a CSV failure. Display formatting may round labels/tooltips, but the API values and chart series retain calculation precision.

## Exclusions

Persistence, changes to historical market data, network acquisition, costs, taxes, dividends, inflation, drawdown, an initial monetary value, and new assets are outside this feature. Existing task 006's unresolved PC-R08 (malformed JSON containing a lone surrogate can produce 500) is not implicitly closed; this task includes a request-error regression for it if reproducible on the current snapshot.
