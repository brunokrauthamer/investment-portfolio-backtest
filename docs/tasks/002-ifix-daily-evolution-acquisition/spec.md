# IFIX daily-evolution acquisition — specification s001

Status: proposed on 2026-11-03; awaiting explicit human approval together with plan p001. No implementation or acquisition is approved by this proposal alone.

## Goal and user decisions

An explicitly invoked Python acquisition command obtains every downloadable IFIX daily-evolution source file offered by the [B3 page](https://sistemaswebb3-listados.b3.com.br/indexStatisticsPage/daily-evolution/IFIX?language=pt-br) from 2011 through the latest period available when it runs. The user chose: “Save original first”; “on a command”; “yes” to replacing updated files after recoverable backup while leaving unchanged files alone; and “just download the files, it is for personal use only”. This does not establish a license or determination of applicable terms.

## Scope and conventions proposed for approval

- Preserve the bytes of each B3 download as received; use a distinct, deterministic local name encoding the B3 period and preserving the actual format/extension. Store under `data/ifix/source/`, never treating backups as active files. Keep source period and original download name in a local manifest. Do not convert, merge, calculate, interpolate or invent financial data.
- On each explicit invocation discover the currently offered periods and process all applicable periods, including past periods that may have changed, through B3's latest available period. Treat the source's actual available period granularity as authoritative; do not assume annual files or that the latest calendar year is fully populated. If a required period cannot be obtained or its availability cannot be established, report incomplete rather than claim success. Preserve earlier successful files even when another period fails.
- Unchanged bytes remain untouched. Before replacing a changed active file, create and verify a recoverable copy at `data/backups/ifix/<period>/<UTC timestamp>-<content hash>-<filename>`. Write each active file to a temporary sibling and atomically replace it only after the backup and download checks succeed. No concurrent invocations: reject a second invocation while the first holds an exclusive lock; stale lock recovery must be documented and never silently break a live lock.
- Network requests occur only after the command is explicitly run, never on module import or application startup. Default TLS certificate verification remains enabled. Use bounded timeouts and conservative request pacing; report B3 errors or access restrictions without bypassing them.
- Document source URL, access date, applicable usage/access information found during source inspection, local layout, execution, partial-failure behavior, backup naming and restore procedure. Personal use is the stated purpose, not proof of a license. If source inspection identifies an actual restriction incompatible with the intended operation, report it and stop affected live acquisition rather than bypassing it.

## Acceptance criteria

- **AC-001 — explicit invocation:** The documented command starts acquisition; imports and application startup do not contact B3. A normal run determines source-offered applicable periods beginning in 2011 and through the most recently offered period at runtime, with no hard-coded final year.
- **AC-002 — original downloads:** For each offered applicable period the command saves the exact downloaded bytes in a distinct stable, period-identifiable active file under `data/ifix/source/`, preserving the actual extension; a manifest records period, original filename, source URL, retrieval time and content hash. No transformed or synthetic financial series is created.
- **AC-003 — completeness and errors:** A complete run reports periods saved, unchanged and updated and exits successfully only when all applicable source-offered periods are accounted for. Missing/unavailable periods, failed or ambiguous discovery, unexpected response/format, invalid downloads, timeouts, access denial and write errors are identified by period or discovery step; the run exits nonzero and never represents partial results as complete. Do not regard unoffered future periods as failures.
- **AC-004 — safe reruns:** Byte-identical files retain their contents and modification time with no new backup. A changed file is backed up and verified outside active inputs before atomic replacement. A failed download, failed backup or failed replacement cannot leave the previous active file partially written or lose it; other completed periods remain usable. Document how to restore the backup.
- **AC-005 — boundaries and concurrency:** A single command invocation owns the destination at a time; an overlapping invocation fails clearly without changing active data. Networking, source-period discovery and download behavior are isolated from local storage and orchestration so each can be tested independently; no unrelated API, scheduler or frontend is introduced.
- **AC-006 — verification and documentation:** Automated tests exercise selection, byte preservation, unchanged/changed reruns, backup/restore and failure paths, including newest available partial period, no available periods, overlap, invalid responses and interrupted writes. Tests use dummy non-market bytes and controlled responses; they do not fabricate historical market observations. Documentation gives install/run instructions and describes source provenance, observed format, limitations and backup/restore.
- **AC-007 — real-source evidence:** Independent QA verifies the documented command against the actual B3 source when access is available, comparing selected source periods and downloaded files with local results, including the earliest requested and latest available periods. The evidence records observed coverage and any B3 unavailability. A blocked live check remains blocked, not passed.

## Exclusions

Financial calculations, normalized or merged CSV output, trading-calendar gap filling, other indices/assets, dashboards or APIs, scheduling, distribution or redistribution, authentication/circumvention, and synthetic market data are outside this increment.

## Source uncertainty and decisions required during implementation

The web reader could not extract the requested IFIX page; its exact available years, period selectors, download mechanism and file format have not been verified. An indexed B3 page for a different index displays year and semester selectors, which is a lead, not evidence that IFIX downloads follow the same scheme. Confirm the actual controls, native files, access terms and expected valid-download checks before choosing adapter details; if source behavior requires changing any acceptance criterion, scope or user convention, return for revised spec/plan approval. An empty offered-period list or inability to distinguish unavailable from incomplete is not success.
